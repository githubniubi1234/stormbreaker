STORMBREAKER: six practical workflows

This tutorial connects prepared input tables to fitted models, evaluation tables and plots. All data are synthetic. Each scenario is a separate packaged script that returns example_result and figures; scripts do not automatically export files or open a browser.

library(stormbreaker)
source(system.file("examples", "scenarios", "01-binary.R",
  package = "stormbreaker", mustWork = TRUE))
figures$ROC

Replace the script name to run another scenario. The illustrated tutorial is also available through vignette(“stormbreaker-short-scenarios”).

Prepare the input

Each row represents one patient and each predictor is a numeric feature.

Input Required columns Meaning
Binary development/evaluation patient_id, outcome, gene_a, gene_b, gene_c outcome is 0/1; 1 is the positive class
Survival development/evaluation patient_id, time, event, gene_a, gene_b, gene_c event is 1 for an observed event and 0 for censoring; declare the time unit
Prediction patient_id and the fitted model’s required features Outcomes are not needed
Explanation background The model’s predictor columns A declared development/reference cohort

Replace the illustrative gene names with your prepared columns and declare them in predictors. Transpose a gene-by-sample expression matrix and align identifiers to clinical records before task construction. Raw sequencing processing, normalization, log transformation, identifier mapping and imputation are upstream steps. External features must use compatible definitions and preprocessing.

The first three rows of the packaged binary development cohort are:

For repeated observations, assign a unique row identifier and declare the patient group:

task <- bi_task(development, "analysis_id", "outcome", genes,
  group_col = "patient_id")

Supported resampling keeps each patient in one fold. This does not change row weights or automatically configure every native engine’s internal resampling. The tutorial CSVs use one row per independent patient.

Follow the objects

Object Constructor Contents
data.frame Prepared CSV/table Identifiers, outcomes and numeric predictors
task bi_task(), surv_task() Data, column roles, units and declared horizons/thresholds
route bi_pipeline(), surv_pipeline() An unfitted selection/prediction specification
comparison compare_cv(), run$comparison Saved cross-validation evidence
fit fit_final(), finished$fit The reusable final model
prediction predict_final() New-sample predictions without outcomes
evaluation eval_external() ID-aligned outcomes, metrics, curves and status
views clinical_plots() Plots, separate captions and availability

Final fitting does not replace CV. Prediction, result tables and clinical views do not train another model. SHAP adds an explanation calculation without refitting.

1. Start with binary classification

This scenario uses 120 development observations, Logistic regression and three folds. The small threshold grid is illustrative. plots=FALSE avoids an additional final fit during comparison; plots are drawn from the saved CV result.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-binary-development.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")

run <- bi_run(development, outcome = "outcome", id = "patient_id",
  predictors = genes, models = "Logistic", folds = 3, seed = 42,
  decision_thresholds = c(.1, .2, .3, .5, .7), plots = FALSE)
comparison <- run$comparison
metrics <- result_table(comparison, metric = "roc_auc")
figures <- list(
  ROC = plot_roc(comparison),
  Calibration = plot_calib(comparison),
  DCA = plot_dca(comparison)
)
example_result <- list(input = development, run = run,
  comparison = comparison, metrics = metrics, figures = figures)

if (interactive()) print(figures$ROC)

run is the workflow object; run$comparison is the comparison. metrics contains the AUC result; figures includes ROC, calibration and decision curves.

pipeline_id metric estimate status scope
none__logistic roc_auc 0.654 success within_outer_assessment_fold

The ROC uses saved out-of-fold predictions and the existing fold-summary convention, not an apparent-training ROC. Access figures$Calibration and figures$DCA for the other views. Decision curves require declared thresholds; use clinically meaningful prespecified values rather than copying a demonstration grid into a study protocol.

2. Compare specified models

Logistic and Gaussian naive Bayes use the same candidate genes and outer folds. compare_cv() compares the declared routes; it does not choose a winner using an external test cohort.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-binary-development.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")
task <- bi_task(development, "patient_id", "outcome", genes)
routes <- list(
  Logistic = bi_pipeline("Logistic"),
  NaiveBayes = bi_pipeline("NaiveBayes")
)
comparison <- compare_cv(task, routes, folds = 3, seed = 42, progress = FALSE)
metrics <- result_table(comparison, metric = "roc_auc")
figures <- list(
  Performance = plot_perf(comparison, metric = "roc_auc"),
  ROC = plot_roc(comparison)
)
example_result <- list(input = development, task = task, routes = routes,
  comparison = comparison, metrics = metrics, figures = figures)

if (interactive()) print(figures$Performance)

3. Evaluate one final model in two cohorts

The development table has 120 observations; validation cohorts A and B have 80 and 70. Their columns agree. finish_run() continues the selected Logistic route without repeating the complete candidate comparison; one final model predicts both cohorts.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-binary-development.csv",
  package = "stormbreaker"), check.names = FALSE)
validation_a <- read.csv(system.file("extdata", "demo-binary-external-a.csv",
  package = "stormbreaker"), check.names = FALSE)
validation_b <- read.csv(system.file("extdata", "demo-binary-external-b.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")

run <- bi_run(development, outcome = "outcome", id = "patient_id",
  predictors = genes, models = "Logistic", folds = 3, seed = 42,
  decision_thresholds = c(.1, .2, .3, .5, .7), plots = FALSE)
finished <- finish_run(run, "Logistic",
  external = list(Validation_A = validation_a, Validation_B = validation_b),
  plots = TRUE)
views <- clinical_plots(finished)
metrics <- do.call(rbind, lapply(names(finished$evaluations), function(cohort) {
  result_table(finished$evaluations[[cohort]], metric = "roc_auc", cohort_label = cohort)
}))
figures <- list(ROC = views$plots$ROC)
example_result <- list(input = development,
  external = list(Validation_A = validation_a, Validation_B = validation_b),
  run = run, finished = finished, views = views, metrics = metrics, figures = figures)

4. Predict survival risk and horizon probabilities

This scenario evaluates Cox risk ranking and six-month survival predictions. It uses 160 development observations and 100 validation observations.

patient_id time event gene_a gene_b gene_c
SDEV_P001 11.233 1 1.371 -0.176 -0.485
SDEV_P002 6.996 1 -0.565 -1.072 0.189
SDEV_P003 12.005 0 0.363 0.163 0.051

Declare time_unit=“month” with prediction_horizon=6. An event is coded as 1 and censoring as 0; follow-up time must not be discarded as though this were an ordinary binary endpoint.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-survival-development.csv",
  package = "stormbreaker"), check.names = FALSE)
validation <- read.csv(system.file("extdata", "demo-survival-external.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")
task <- surv_task(development, "patient_id", "time", "event", genes,
  time_unit = "month", prediction_horizon = 6,
  decision_thresholds = c(.1, .2, .3, .5, .7))
route <- surv_pipeline("Cox")
cv <- run_cv(task, route, folds = 3, seed = 42, progress = FALSE)
fit <- fit_final(task, route)
prediction <- predict_final(fit, validation[c("patient_id", genes)], "patient_id")
endpoint <- surv_endpoint(validation, "patient_id", "time", "event",
  time_unit = "month", prediction_horizon = 6)
evaluation <- eval_external(prediction, endpoint)
metrics <- result_table(evaluation, metric = "harrell_c", cohort_label = "Validation")
horizon_metrics <- do.call(rbind, lapply(c("time_auc", "ipcw_brier"), function(metric) {
  result_table(evaluation, metric = metric, cohort_label = "Validation")
}))
figures <- list(Calibration = plot_calib(evaluation), DCA = plot_dca(evaluation))
example_result <- list(input = development, external = validation, task = task,
  cv = cv, fit = fit, prediction = prediction, endpoint = endpoint,
  evaluation = evaluation, metrics = metrics, horizon_metrics = horizon_metrics, figures = figures)

if (interactive()) print(figures$Calibration)

Predictions retain risk and survival probability. Concordance and horizon-specific metrics are separate tables; the latter preserve the time and unit.

A risk score is not a probability. survival_probability is the probability of remaining alive at the specified horizon; decision curves use its event-risk complement. Time-dependent AUC differs from ordinary binary ROC. Without a prediction horizon, absolute-probability calibration and horizon-specific decision curves are unavailable.

5. Select features and inspect native diagnostics

The ordered route is Lasso selection followed by Logistic prediction. It needs glmnet, installed by the user. capture_diagnostics=TRUE retains native evidence during fitting rather than refitting when a plot is requested.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-binary-development.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")
task <- bi_task(development, "patient_id", "outcome", genes)
route <- bi_pipeline(c("Lasso", "Logistic"))
fit <- fit_final(task, route, capture_diagnostics = TRUE)
diagnostics <- plots(fit)
retained_genes <- data.frame(gene = fit$required_features)
coefficients <- model_coefs(fit, reference_data = development[genes])
figures <- c(diagnostics$plots, list(Coefficients = plot_coefs(coefficients)))
example_result <- list(input = development, task = task, route = route, fit = fit,
  genes = retained_genes, diagnostics = diagnostics,
  coefficients = coefficients, figures = figures)

if (interactive()) print(figures$Coefficients)

The coefficient path and final-model coefficients are separate views. Inspect diagnostics$unavailable when evidence is absent; an older saved fit cannot supply a path it never retained. selected_genes() applies to independent method-analysis results rather than arbitrary fitted model objects.

Additional routes can be defined explicitly:

bi_pipeline(c("mRMR", "xgboost_linear"))
bi_pipeline(c("RF", "mclustda_bic"))

These are unfitted specifications requiring suitable data and optional engines.

6. Explain individual predictions

The example first prepares a Logistic model. For an existing model, load the saved fit instead. Query data contain only identifiers and features; background features come from development data.

library(stormbreaker)

development <- read.csv(system.file("extdata", "demo-binary-development.csv",
  package = "stormbreaker"), check.names = FALSE)
validation <- read.csv(system.file("extdata", "demo-binary-external-a.csv",
  package = "stormbreaker"), check.names = FALSE)
genes <- c("gene_a", "gene_b", "gene_c")

task <- bi_task(development, "patient_id", "outcome", genes)
fit <- fit_final(task, bi_pipeline("Logistic"))
query <- validation[1:8, c("patient_id", genes)]
background <- development[genes]
shap <- model_shap(fit, query, "patient_id", background_data = background,
  permutations = 16, background_n = 12, seed = 42)
figures <- list(
  Importance = plot_shap_imp(shap),
  Beeswarm = plot_shap(shap, feature_values = query, id_col = "patient_id"),
  Dependence = plot_shap_dep(shap, "gene_a", query, "patient_id"),
  Waterfall = plot_shap_one(shap, row = 1)
)
example_result <- list(input = development, task = task, fit = fit,
  query = query, background = background, shap = shap, figures = figures)

if (interactive()) print(figures$Beeswarm)

shap$contributions is an eight-sample by three-feature matrix. The reference value plus a row’s contributions reconstructs that sample’s saved model score. Here model_shap() explains positive-class probabilities using an approximate permutation estimator, not exact TreeSHAP. Sixteen permutations keep the example small; assess approximation stability for your application.

gene_a gene_b gene_c
EXTA_B001 0.1917 -0.0428 -0.0072

Use figures$Importance and figures$Dependence for the other views. SHAP describes this model and background, not causal effects or automatically selected clinical thresholds.
